# Python 서버 내부 동작 상세 문서

## 1. 전체 실행 흐름

```
uvicorn 시작
    │
    ├─ FastAPI 앱 로드
    │   └─ @startup → detection_loop() 스레드 시작
    │
    ├─ [detection_loop 스레드] ──────────────────── 무한 루프
    │   ├─ 웹캠 프레임 읽기 (OpenCV)
    │   ├─ MediaPipe 추론
    │   ├─ 점수 계산
    │   ├─ state 딕셔너리 업데이트 (lock)
    │   ├─ 프레임 base64 인코딩 저장 (lock)
    │   └─ cv2.imshow 로컬 창 표시
    │
    └─ [WebSocket /ws] ──────────────────────────── 클라이언트마다
        └─ 20fps 로 state + frame → JSON 전송 → Flutter
```

## 2. 모델 다운로드 단계

서버 시작 시 `.task` 파일이 없으면 자동 다운로드.

```
pose_landmarker_heavy.task  (~30MB)  — Google MediaPipe CDN
```

- 실패 시 `sys.exit(1)` 로 서버 종료

## 4. 카메라 열기

```python
for idx in (0, 1, 2):
    cap = cv2.VideoCapture(idx, cv2.CAP_DSHOW)
    # CAP_DSHOW = Windows DirectShow 백엔드
    # 일반 VideoCapture(0) 는 Windows에서 열려도 프레임 안 나오는 경우 있음
    if cap.isOpened():
        ret, _ = cap.read()   # 실제 프레임 오는지 확인
        if ret: break
```

- 인덱스 0, 1, 2 순서로 시도 → 처음 성공한 카메라 사용
- `CAP_DSHOW` 없으면 Windows에서 카메라가 안 열리는 경우 많음

## 5. 캘리브레이션 (5초)

```
elapsed < 5초 동안:
    매 프레임마다 아래 4개 값을 리스트에 수집
    ├─ ear_vis  : 귀 가시성 평균
    ├─ z_diff   : 어깨 z - 귀 z 차이
    ├─ pitch    : solvePnP 머리 피치각
    └─ eye_ratio: 눈-어깨 수직 비율

5초 후:
    golden = 각 리스트의 평균값
    → 이후 모든 점수는 golden 대비 편차로 계산
```

**왜 캘리브레이션이 필요한가?**
- 카메라 높낮이, 개인 체형, 앉는 거리가 다 다름
- 절대값 기준이 아니라 "바른 자세 대비 얼마나 달라졌는지"로 판단
- 같은 코드로 키 165cm / 185cm 모두 동작 가능

## 6. MediaPipe 추론 (매 프레임)

```python
# BGR → RGB 변환 (MediaPipe는 RGB 입력)
rgb    = cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)
mp_img = mp.Image(image_format=mp.ImageFormat.SRGB, data=rgb)

# 타임스탬프 필수 (VIDEO 모드에서 단조증가 보장)
timestamp_ms = int((time.time() - start_time) * 1000)

pose_result = pose_lmk.detect_for_video(mp_img, timestamp_ms)
face_result = face_lmk.detect_for_video(mp_img, timestamp_ms)
```

### Pose 랜드마크 인덱스 (주요 사용)

```
0  = NOSE
7  = LEFT_EAR
8  = RIGHT_EAR
11 = LEFT_SHOULDER
12 = RIGHT_SHOULDER
23 = LEFT_HIP
24 = RIGHT_HIP
```

각 랜드마크: `.x`, `.y` (0-1 정규화), `.z` (상대 깊이), `.visibility` (0-1)

### Face 랜드마크 인덱스 (주요 사용)

```
1   = 코 중심
33  = 오른눈 외측
57  = 오른 입꼬리
133 = 오른눈 내측
152 = 턱 끝
263 = 왼눈 외측
287 = 왼 입꼬리
362 = 왼눈 내측
```

## 7. 점수 계산 4가지 지표

### 7-1. pitch (머리 피치각) — 가중치 40%

```
solvePnP 알고리즘:
  입력: 얼굴 6개 2D 픽셀 좌표 (코, 턱, 양눈, 양입꼬리)
       + 실제 3D 기준점 (mm 단위 얼굴 모델)
  출력: 회전 벡터 (rvec) → Rodrigues 변환 → 회전 행렬
  피치각 = atan2(rmat[2][1], rmat[2][2]) (도 단위)

점수화:
  s_pitch = 1 - (현재 피치 - golden 피치) / 12도
  → 기준보다 12도 더 숙이면 s_pitch = 0 (최악)
  → 기준과 같으면 s_pitch = 1 (최상)
```

**왜 solvePnP?**
- 2D 카메라로 3D 머리 회전각을 추정하는 표준 방법
- MediaPipe z 좌표는 부정확하지만 solvePnP는 얼굴 기하학 이용해 정확한 각도 계산

### 7-2. eye (눈-어깨 수직 비율) — 가중치 30%

```
eye_y      = 4개 눈 랜드마크 y좌표 평균
shoulder_y = 좌우 어깨 y좌표 평균
eye_ratio  = |eye_y - shoulder_y| / 어깨너비

점수화:
  s_eye = (현재 비율 / golden 비율 - 0.7) / 0.3
  → 머리가 내려가면 비율 감소 → 점수 감소
```

**정면 카메라에서 FHP 감지 핵심 지표**
- 거북목이 되면 머리가 앞으로 & 아래로 → 눈이 어깨에 가까워짐
- 어깨너비로 나눠서 거리 차이를 정규화 (앉는 거리 무관)

### 7-3. vis (귀 가시성) — 가중치 15%

```
ear_vis = (왼귀 visibility + 오른귀 visibility) / 2

점수화:
  s_vis = 1 - (golden_vis - 현재_vis) / 0.15
  → 고개가 앞으로 숙이거나 돌아가면 귀 visibility 감소
```

### 7-4. z (어깨-귀 z축 차이) — 가중치 15%

```
curr_z = 어깨 z 평균 - 귀 z 평균

점수화:
  s_z = 1 - (curr_z - golden_z) / 0.1
  → 머리가 앞으로 나올수록 귀 z 감소 → 차이 증가 → 점수 감소
```

## 8. E2E (End-to-End) 구조 설명

현재 구조는 **규칙 기반 E2E**:

```
[원본 이미지]
    ↓
[전처리: BGR→RGB, 리사이즈]
    ↓
[MediaPipe 특징 추출]          ← 딥러닝 모델 (내부)
    ├─ 33개 포즈 랜드마크
    └─ 478개 얼굴 랜드마크
    ↓
[기하학 계산]                  ← 규칙 기반
    ├─ solvePnP 피치각
    ├─ 눈-어깨 비율
    ├─ 귀 가시성
    └─ z축 차이
    ↓
[캘리브레이션 보정]
    ↓
[가중치 합산 → 최종 점수]
    ↓
[Flutter로 전송]
```

### 순수 딥러닝 E2E 추가 방법 (향후)

```
[원본 이미지]
    ↓
[얼굴+목 크롭]                 ← FaceLandmarker bbox 활용
    ↓
[MobileNetV3 CNN]             ← turtle_neck_model.pth 필요
    ↓ 0-1 (1=거북목)
[기하학 점수와 가중치 합산]
    └─ geo 60% + CNN 40%
```

- `server/` 폴더에 `turtle_neck_model.pth` 파일을 넣으면 자동 활성화 예정
- 현재는 학습 데이터 없으므로 기하학 100%로 동작

## 9. Flutter 전송 구조

```
detection_loop 스레드
    → state 딕셔너리 업데이트 (threading.Lock)
    → _latest_frame 업데이트 (threading.Lock)

WebSocket 핸들러 (asyncio, 20fps)
    → state + frame 읽어서 JSON 직렬화
    → websocket.send_json()

Flutter
    → jsonDecode → PostureState.fromJson()
    → base64Decode(_data.frame) → Image.memory()
    → setState() → UI 리렌더링
```

### 전송 JSON 예시

```json
{
  "status":    "ok",
  "score":     87,
  "countdown": 0,
  "is_fhp":    false,
  "scores": {
    "pitch": 0.91,
    "eye":   0.85,
    "vis":   0.98,
    "z":     0.76
  },
  "frame": "/9j/4AAQSkZJRgAB..."
}
```

## 10. 스레드 안전성

| 공유 자원 | 보호 방법 |
|-----------|-----------|
| `state` 딕셔너리 | `state_lock` (threading.Lock) |
| `_latest_frame` 문자열 | `_frame_lock` (threading.Lock) |
| `score_buf`, `sub_bufs` | detection_loop 단독 접근 (lock 불필요) |

- detection_loop: 쓰기 전용
- WebSocket 핸들러: 읽기 전용
- lock 범위 최소화로 프레임 드랍 없음

## 11. 팀 내부 배포 방법 (Python 설치 필요)

### 1단계 — Flutter Windows 빌드

```bash
cd tirtle_ml
flutter build windows
```

빌드 결과물 위치:
```
tirtle_ml/build/windows/x64/runner/Release/
```

### 2단계 — server/ 폴더 복사

빌드 폴더 안에 `server/` 폴더를 직접 복사한다.

```
Release/
├─ tirtle_ml.exe          ← Flutter 앱 실행 파일
├─ server/                ← 프로젝트 루트의 server/ 폴더를 여기에 복사
│   ├─ server.py
│   └─ requirements.txt
├─ flutter_windows.dll
└─ (기타 dll 파일들)
```

### 3단계 — 받는 사람 PC 설정 (최초 1회)

Python 3.9 이상이 설치되어 있어야 한다.

```bash
cd Release/server
pip install fastapi "uvicorn[standard]" mediapipe opencv-python numpy
```

MediaPipe `.task` 모델 파일(약 60MB)은 서버 최초 실행 시 자동 다운로드된다.
인터넷 연결이 필요하며 이후 재실행 시에는 다운로드하지 않는다.

### 4단계 — 실행

`tirtle_ml.exe` 를 더블클릭하면 된다.
앱이 시작될 때 `"포스처가드 서버"` 콘솔 창이 자동으로 열리며 서버가 시작된다.
앱을 X버튼으로 닫으면 서버도 함께 종료된다.

### 배포 시 주의사항

| 항목 | 내용 |
|------|------|
| Python 버전 | 3.9 이상 권장 (mediapipe 호환성) |
| 카메라 | DirectShow 지원 웹캠 필요 (대부분의 USB 웹캠 해당) |
| 방화벽 | 포트 8000이 localhost에서만 사용되므로 별도 허용 불필요 |
| 모델 파일 | 최초 실행 시 인터넷 연결 필요 (이후 오프라인 가능) |
| 배포 파일 크기 | Release 폴더 약 30MB + Python 패키지 약 1GB (대상 PC에 설치) |
